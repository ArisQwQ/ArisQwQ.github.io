## 线上首页文字消失 —— 根因：Cloudflare 邮箱混淆破坏 hydration

- 现象：GH Pages 部署后首页 Hero 只剩头像，标题/简介/社交图标全部不可见；CF Pages 那份正常。
- 排查结论（`curl` 线上 HTML）：
  - `<h1 id=hero-title style="opacity:0;transform:translateY(30px)">` —— Hero 文案由 framer-motion 入场动画从 hidden 动画到 visible，**依赖 JS hydration**。
  - 线上 HTML 里 `mailto:` 数量为 **0**，全部被 Cloudflare 改写成 `/cdn-cgi/l/email-protection#...`，并注入 `cdn-cgi/scripts/.../email-decode.min.js`。
  - 因此 React hydration 时真实 DOM 与虚拟 DOM 不一致（mismatch）→ hydration 失败 → framer-motion 不接受控 → `opacity:0` 永远保持。
  - 头像可见是因为它是裸 `<img>`，没有包 motion。
  - 无 rocket-loader 注入，Email Obfuscation 是唯一改写源。
- 修复方向：① CF → Scrape Shield → Email Address Obfuscation 关闭（最快）；② blog 记录改 DNS only 灰云，CF 完全不介入；③ 代码层面让 Hero 不依赖 JS 也能显示（CSS 动画或去掉 initial hidden）。
- 相关：`arisqwq.github.io` 会 301 到自定义域名（Pages 设置里已填 custom domain），且目标是 `http://`（未开 Enforce HTTPS）。
- **结论（02:29 已恢复）**：关掉 CF 的 Email Address Obfuscation 后，HTML 里 `mailto:` 恢复原样（`cdn-cgi/l/email-protection` 归 0），叠加浏览器/边缘 `max-age=600` 缓存过期，首页文字正常显示。属于「CF 改写 HTML → hydration mismatch → framer-motion 卡在 opacity:0」+ 缓存的叠加现象。
- 脆弱点仍在：Hero 的三个元素（h1 / p / socials）SSR 时是 `style=opacity:0`，完全依赖 JS hydration 后动画才有可见度。任何导致 JS 失败或 HTML 被第三方改写的因素都会让文字整片消失。根治方案是把入场动画改成不依赖 JS（CSS animation 或去掉 initial hidden）。
- CF Pages 仍保留在 `cfblog.tendou-aris.com`，`blog.tendou-aris.com` 走 GH Pages（经 CF 代理，橙云）。
- **最终确认（02:32）**：手机/无痕正常、仅本机异常 → 就是浏览器缓存残留，强刷后彻底恢复。以后同类「线上和本地不一致」的问题，先让用户开无痕对比，能立刻区分是缓存还是真故障。

## 深淺色切換圖示修正（兩態）

- 根因：`src/theme/Navbar/ColorModeToggle/index.tsx` 是**舊版 swizzle 遺留**，傳給 `ColorModeToggle` 的是 `value={colorMode}`（只有 light/dark），而 theme-classic 3.10.1 官方版本傳的是 `colorModeChoice`（可為 null＝跟隨系統）並帶 `respectPrefersColorScheme`。
- 圖示實由 CSS 依 `html[data-theme-choice]` 決定：首訪該值為 `system` → 顯示「顯示器」圖示，與實際深/淺色不符。
- 方案（用戶選定「兩態、圖示跟著外觀走」）：新增 swizzle `src/theme/ColorModeToggle/index.tsx` + `styles.module.css`，只渲染太陽/月亮兩個圖示，顯示由 `[data-theme='dark'] .moonIcon` 與 `html:not([data-theme='dark']) .sunIcon` 控制，不依賴 JS、hydration 前即正確；點擊為 light⇄dark，title/aria 用繁體（切換到淺色/深色模式）。
- 原 Navbar 包裝組件不需改動（value=colorMode 正好是有效外觀）。
- 驗證：build 成功（`--out-dir /home/aris_qwq/arisblog-preview8`），CSS 內僅剩我們的新規則、`data-theme-choice` 圖示規則已消失，HTML 只輸出 sunIcon/moonIcon 各一。
- 副作用：點擊後無法再回到「跟隨系統」（localStorage 寫入明確值），這是兩態方案的預期取捨。
